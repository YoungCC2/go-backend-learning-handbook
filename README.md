# Go 从入门到中级：学习与查阅手册

这套手册面向准备从零开始学习 Go、最终达到中级后端开发能力的学习者。

中级的判断标准不是“学完多少语法”，而是：能够独立设计、开发、测试、部署和排查一个可上线的 Go 服务，并能解释关键技术选择。

## 手册目录

1. [中级 Go 技术地图](./01-skill-map.md)：学习内容、掌握深度和常用工具速查。
2. [从零到中级学习路线](./02-study-roadmap.md)：按阶段学习，每阶段都有成果和通关标准。
3. [贯穿式实战项目](./03-practice-project.md)：用一个订单系统逐步覆盖 Go 后端核心技术。
4. [能力检查与面试清单](./04-competency-checklist.md)：判断自己是否达到中级，以及复习时查漏补缺。
5. [中级 Go 能力思维导图](./05-mind-map.md)：从语言、并发到项目实战的全局知识结构。

## 推荐用法

- 第一次学习：以学习路线为主线，不要按照技术地图从头背到尾。
- 遇到陌生概念：回到技术地图查询它属于哪一层、需要掌握到什么程度。
- 每学完一个阶段：完成阶段成果，并用通关标准自测。
- 每两周复盘一次：在能力检查表中标记“不了解、会使用、能解释、能排障”。
- 所有代码都放入 Git 仓库；每个功能使用小提交，README 记录运行方法和设计取舍。

## 中级能力模型

| 层次 | 典型表现 |
|---|---|
| 初学 | 能看懂语法，在指导下完成小功能 |
| 初级 | 能独立完成普通 CRUD 接口和简单测试 |
| 中级 | 能负责一个服务，处理并发、数据一致性、性能、部署与线上问题 |
| 高级 | 能主导复杂系统设计、容量规划、跨团队治理与技术演进 |

## 学习原则

1. 先标准库，再框架。先理解 `net/http`，再使用 Gin 或 Go-Zero。
2. 先做单体，再拆微服务。没有真实复杂度时，不要为了“高级”而堆组件。
3. 每个知识点都经历四步：理解概念、写最小示例、用于项目、制造并排查故障。
4. 框架 API 可以查文档；并发、数据库、网络、测试和排障能力必须形成自己的理解。
5. 项目质量比项目数量重要。一个不断演进、有测试和文档的项目胜过十个 CRUD Demo。

## 建议时间投入

从零开始、每周投入 10–15 小时，通常需要 6–9 个月形成较完整的中级能力。已有其他语言后端经验时，可以压缩语法阶段，但不要跳过 Go 并发模型、工程工具链和运行时诊断。
